# Evaluation implementation decisions

- Tokens are whitespace-delimited after NFKC normalization; this preserves case and punctuation without introducing an undeclared linguistic tokenizer.
- Run 3 supersedes raw textContent: shared extractText inserts spaces at semantic block boundaries, br, li, td and th, skips head/script/style/template/noscript, preserves inline character adjacency, and never mutates supplied DOM nodes. The fixed HTML tag list avoids dependence on CSS layout/network resources and is shared with annotators/checking.
- Presence/noise LCS uses lexicographically earliest output-token index sequence, then earliest reference-token sequence; this makes repeated text deterministic.
- Review 1 supersedes the earlier per-text/exact-first interpretation: one consumed-output-token set applies across ALL content units, including different or nested texts. Units of at least five tokens take the earliest qualifying LCS start after the previous position, then anywhere unused, without preferring a later exact substring. For the same start, use its longest continuation and the existing earliest-index tie-breakers so fully available matching tokens are consumed rather than arbitrarily stopping at the threshold. Short units retain exact-substring presence and use the earliest unused intersecting token span.
- Independent unit presence and recall remain unchanged; if a present unit has no unused occurrence, its order position is null and order tau is zero, so an output cannot gain a clean pass by silently dropping unassigned order evidence. Optional content units also participate in consumption, in reference order.
- Short-unit occurrences use the declared exact substring (including cat inside concatenate); their order position is the containing output token. Noise character share keeps its independent original token LCS.
- Characters are normalized Unicode code points; JavaScript UTF-16 offsets are used only to locate token spans, so supplementary-plane characters are not double-weighted.
- Noise character spans exclude inter-token spaces; the denominator includes all normalized output characters, following the declared output-token-span numerator.
- Order uses Kendall tau-b for tied output positions, 1 for fewer than two present required units and 0 for an entirely tied multi-unit order; ties must not become false concordances.
- Title-first requires every annotated title and every other required unit to be present, and each title to precede those other units; missing units cannot establish a first-position claim.
- References without a title cannot pass complete; references without required content or with empty unit text are rejected rather than silently scored.
- No noise annotations means leakage and noise share are zero; empty output has zero noise share, with recall/title failures retained.
- P0 and P1 deliver their own extraction with fallback=false; P2 failures deliver empty output and remain in the denominator, with no unrequested reader recovery.
- P2-nr exposes the original private render function in a VM via one guarded export insertion; the production file remains unchanged and sanitization is not copied or approximated.
- P2-nr applies October's nonpositional predicate to main and exclusions, validates all CSS selectors, and requires exactly one main match outside the core noise filter; exclusions may match zero or multiple nodes.
- Bootstrap samples sites uniformly with replacement and retains all pages of each sampled site; estimates and resampled means are page-weighted. Percentile intervals use linear quantile interpolation.
- Paired comparisons require identical page IDs and site bindings; subset selection in baseline runs is explicit for policies whose candidates cover fewer pages.
- Candidate absence skips P2/P2-nr only; supplied but invalid or unreadable candidates produce counted failure rows for both policies. Missing references are separately listed pending annotation.
- Baseline outputs refuse an existing result folder, preserve source/reference/output hashes, and store HTML beside JSONL for coordinator inspection; baseline latency is local extraction only, not browser or comparative performance evidence.
- P1's reading HTML is Readability's `content`; its separately returned metadata title is reported but not prepended, avoiding invented content outside the parser's extraction.
- Node 22 needs an index.js directory entry point for the exact requested `node --test tests/revision/eval` invocation; it requires the registered test files explicitly.
- October smoke replay uses the six final-study candidate contracts and prepared44-v2 source bindings, verifies candidate/outcome/source hashes, and labels results as current jsdom execution diagnostics rather than historical browser scores.
- While the canonical development manifest is pending, run-available-dev snapshots existing reference/meta pairs into a results-only manifest; it switches to dev-manifest.json once that file exists, and never changes corpus artifacts.
- Canonical nested sites/pages manifests inherit host/siteId and resolve dev/<siteId>/<pageId> folders; flat manifests remain supported.
- Fresh and shared P2 use separate runs (CLI third argument fresh/shared); shared mode requires explicit seedId/inductionPageId, compiles the seed once, checks seed/site/source bindings, then applies its procedure unchanged. P2-nr applies that same seed's raw main/exclude on each target without compilation.
- Candidate provenance records original file expected/observed hashes and resolved path separately from the logical rule hash; capture hashes bind raw bytes before decoding.
- Paired statistics reject differing source hashes, reference hashes or threshold sets, and failure summaries retain stable categories alongside full diagnostic strings.
- Output writers verify real-path containment and exclusively create the final folder, preventing junction escapes and concurrent JSONL mixing.
- A zero token-presence threshold is rejected: zero-match units have no declared LCS order and should not be labelled present.
- Frozen receipt replay verifies attempt identity, result hash and provider request identity; a bound failed attempt produces failure rows without requiring a nonexistent candidate artifact.
- CLI corpus/October runs isolate each policy operation (including shared compilation) in a subprocess with a 60,000 ms default timeout, configurable programmatically; a large W3C page otherwise stopped progress for several minutes. Timeouts remain runtime failures with null latency, and partial runs are preserved. Scoring and bootstrap remain in the parent.
- Because blind references were revised during the development run, each result folder snapshots the exact manifest and per-page reference bytes used; row hashes bind those snapshots, so later annotation changes cannot erase the scoring input version.
- Per-page snapshot and HTML writes are exclusive: even adversarial page IDs that collide after UTF-8 encoding fail before overwriting earlier evidence.
- Run 2 fixes the installed cssstyle 5.3.3 TypeError for variable border shorthand followed by longhand declarations via a scoped setProperty wrapper. It skips only the exact failing decorative border declaration, preserves original style markup/DOM and all other declarations, restores the prototype after synchronous operations, and records skip counts. No dependency or production files change.
- Clean-failure attribution reports overlapping recall/title/order/noise counts plus disjoint combinations; title-first failures are a separate diagnostic because section 3 does not make title-first an extra clean-pass gate.
- Each new row/score binds the revised scoring version; paired statistics reject mixed scoring versions even when thresholds and references match.
- P0's default subprocess limit is now 120,000 ms, explicitly authorized by the coordinator for Run 3; other policies/compilation retain 60,000 ms and the P0 algorithm remains unchanged.
- Scoreboard policy coverage is the manifest's common valid-reference cohort; missing metadata or HTML stays as a counted failure, while invalid references are listed and excluded consistently from all policies. Intentional held-out-only comparisons need a held-out-only manifest.
- Scoreboard rescoring deliberately uses the supplied references and current scoring version, preserving older input reference/version identifiers as provenance; source and supplied output hashes must still match.
- A failed own-policy attempt with delivered fallback HTML keeps ok=false for failure accounting but scores the delivered artifact; fallback=true always prevents no-fallback pass. This keeps outcome quality separate from rule failure.
- Scoreboard metadata requires explicit ok/fallback/modelRequests; optional token fields default to zero, invalid numeric fields are flagged and zero-normalized, and raw input JSONL is snapshotted. Shared generation accounting must be assigned once or reported separately, never inferred from outputs or duplicated across targets.
- Exact LCS uses bounded sparse matches (100,000 maximum) or rolling-row/checkpoint DP (200 million cells; 32 MiB DP workspace). Over-budget work raises lcs-resource-limit explicitly rather than exhausting memory or altering a scientific score. Both paths preserve earliest output/reference tie-breakers; the 10,000-token review reproduction is tested under a 128 MiB subprocess heap.
- All content required flags must be booleans in both direct scoring and shared validation; invalid or missing flags reject the reference instead of excluding units silently.
- Audited subsets use only reference audited:true or audit.status=audited metadata, retain all policy failures for those pages, and receive separate estimates/site tables/paired differences. These are included within the overall cohort, never additional observations.
